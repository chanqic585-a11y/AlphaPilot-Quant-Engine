# AlphaPilot V13.21.0 Live Safety Candidate Boundary

## Purpose

V13.21 bridges a fully validated OKX Demo release to a manual Live review
package while deliberately keeping execution impossible.

## Promotion requirements

- Demo status is `demo_validated` or `demo_completed`.
- At least 50 closed Demo trades across at least 30 calendar days.
- Net profit factor is at least 1.15 and maximum drawdown is below 5%.
- Outcome ledger and code/data/model checksums match.
- Symbol, regime, and time stability checks pass.
- No unresolved critical drift event exists.
- A reviewed Demo rollback target is present.

## Fixed risk boundary

- Capital limit: 1000 USDT.
- Risk per trade: 0.25%.
- Maximum open risk: 1%.
- Maximum order notional: 250 USDT.
- Maximum concurrent positions: 3.
- Maximum leverage: 2x.
- Daily loss stop: 2%.
- Drawdown stop: 5%.

## Execution boundary

The exported package binds the Demo release, evidence, lineage, rollback target,
and proposed risk budget by checksum. Manual approval means only
`approved_for_future_release_review`. It does not create an order permission.

Control Console audits request expiry, idempotency, instrument status, price
deviation, reconciliation, circuit breaker, restart state, and kill switch.
Even when all checks pass, the terminal state is
`validated_execution_disabled`. No Live adapter, credential store, account read,
position read, order endpoint, or Withdraw path is implemented.
