# AlphaPilot V13.27.1.6 - Resumable Workflow Worker

The dual-layer backtest CLI now acquires an operating-system file lock scoped to
the workflow run before executing. The lock file lives beside the run artifacts
as `.worker.lock`; process termination releases the lock automatically while the
file remains reusable.

This permits safe restart behavior:

1. The workflow registry retains the same `workflowRunId` and progress payload.
2. Official-data collection retains partition checkpoints and hashes.
3. A restarted worker reuses completed phases and partitions.
4. A concurrent duplicate worker sees the held lock and exits without changing
   workflow state.
5. An explicitly paused workflow is not automatically queued by startup
   recovery.

No schema change, strategy-rule change, credential handling, or execution
permission is introduced.
