# AlphaPilot V13.13.0 Evolution and ML

V13.13.0 adds a bounded factor-evolution loop, offline model primitives, and a
strict strategy-candidate contract. The production cycle stops at
`shadow_research` because no registered V13.12-compatible FactorRun training
dataset exists yet.

## Restricted Factor Generation

Candidates may come only from already parsed and validated ASTs through:

- approved window substitutions
- same-type approved field substitutions
- `safe_add` or `safe_multiply` crosses between validated parents

Candidate count is capped. Unknown fields, invalid windows, future references,
arbitrary source code, and unapproved functions are never emitted.

Canonical expression IDs remove alias, number-format, and commutative
duplicates before evaluation. A separate correlation filter rejects absolute
correlation above a configured threshold and rejects constant or non-finite
series without imputation.

## Research Bandit

The UCB-style Bandit allocates integer evaluation units using prior research
reward, exploration, novelty, and compute-cost penalties. Its output contains
candidate IDs and research units only. It has no symbol, order, position size,
leverage, execution action, Demo release, or live approval field.

## Offline Models

Available deterministic model primitives:

- standardized Logistic Regression baseline
- gradient-boosted decision-stump challenger
- Platt probability calibration
- reliability bins, Brier score, log loss, and accuracy

Training fails unless every referenced FactorRun is registered, complete,
point-in-time validated, and aligned with a purged walk-forward manifest whose
sample count matches the materialized feature matrix. Models are immutable and
may enter only draft/shadow states.

Champion/challenger comparison requires lower log loss, lower Brier score,
minimum walk-forward folds, cost stress, stability, and calibration. Passing
only requests `shadow_approved`; it never replaces a Demo champion.

## Strategy Candidate Contract

A StrategyCandidate requires:

- explicit market, timeframe, exchange scope, and historical universe policy
- long, short, or both direction
- validated factor-expression entry IDs
- stop loss, take profit, and maximum holding period
- at least 2R reward/risk
- risk per trade at most 1%, leverage at most 5, bounded concurrency
- registered DataSnapshot, point-in-time FactorRuns, research-validated Experiments
- a purged walk-forward manifest and passed formal gate

Incomplete contracts are rejected before any StrategyCandidate row is created.
Valid contracts remain `shadow_candidate` with execution, Demo promotion, and
live promotion disabled.

## Safety Boundary

- No API key use or storage.
- No Trade API or Withdraw API.
- No private exchange access.
- No online model mutation.
- No automatic StrategyCandidate creation without formal evidence.
- No DemoRelease or live release.
- No order creation or automatic trading.

V13.14.0 can add automatic Demo promotion only after explicit hard gates and a
separate Demo release contract; this Phase 3 cycle cannot perform that action.
