# AlphaPilot V13.26.0 - Formal Execution Outcome Feedback

V13.26 imports only complete, reconciled OKX Demo or Live Canary trade outcomes
into the immutable offline Outcome Ledger.

## Accepted evidence

Each outcome must be closed and include ordered decision, entry, and exit
timestamps; entry/exit prices; quantity; gross PnL; fees; slippage; net PnL;
risk amount; gross/net R; exit reason; and source payload checksum. Net PnL and
R multiples are recalculated during import.

Every record must resolve to an existing DataSnapshot, StrategyCandidate, and
matching immutable release checksum. Live outcomes additionally require the
exact Live RiskProfile id and checksum.

## Quarantine boundary

An opening order marked `filled` is not a closed trade. Missing exit evidence,
missing parent records, checksum mismatches, ambiguous paths, account values,
and malformed records remain quarantined. The importer never invents lineage
or substitutes defaults.

## Offline-only feedback

Accepted records can enter the bounded V13.22 offline feedback loop. The loop
cannot update an online model, mutate a running release, promote a strategy,
or create an order. Forward, Demo, Live candidate, and Live release checksums
are compared before and after the run.

Run the report:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_v13_26_execution_feedback.ps1
```

No credentials or private account values are read by the report. Withdraw is
not implemented.
