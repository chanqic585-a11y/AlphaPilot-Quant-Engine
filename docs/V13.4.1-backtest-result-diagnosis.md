# V13.4.1 Backtest Result Diagnosis

V13.4.1 diagnoses the first real V13.4 smoke backtest result for
AlphaPilot Volume Rebound V0.1.

This version does not tune strategy parameters, does not enter Dry-run, and does
not modify `AlphaPilotVolumeReboundV01.py`.

## Inputs

Primary source report:

```text
reports/v13_4_smoke_backtest_report.json
```

The source report is a real converted Freqtrade result:

```json
{
  "isMock": false
}
```

The diagnosis also reads the local Freqtrade zip result referenced by the source
report:

```text
user_data/backtest_results/backtest-result-2026-07-04_17-07-53.zip
```

## Outputs

```text
reports/v13_4_1_diagnosis_report.json
reports/v13_4_1_diagnosis_summary.md
docs/v13_4_1_diagnosis_findings.md
```

## Command

```powershell
python -m alphapilot.reports.diagnose_backtest_result
```

Optional explicit paths:

```powershell
python -m alphapilot.reports.diagnose_backtest_result --report reports/v13_4_smoke_backtest_report.json --output reports/v13_4_1_diagnosis_report.json --summary reports/v13_4_1_diagnosis_summary.md
```

## Diagnosis Scope

The diagnosis covers:

- overall metrics
- pair breakdown
- monthly breakdown
- exit reason breakdown
- holding time breakdown
- cost analysis
- consecutive loss analysis
- filter effectiveness availability
- approximate trade quality review from `min_rate` / `max_rate`
- V0.2 candidate ideas
- do-not-change-yet guardrails

## Safety Boundary

V13.4.1 reads local backtest artifacts only.

It does not:

- use real API keys
- call Trade API
- call Withdraw API
- read a real account
- read real positions
- create real orders
- auto trade
- execute Dry-run
- modify the mobile app

## Conclusion

V13.4 pipeline passed, but the V0.1 smoke result is negative:


AlphaPilot Volume Rebound V0.1 must not enter Dry-run. The next step is to use
