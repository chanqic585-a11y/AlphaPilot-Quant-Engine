# V13.4.3 Strategy V0.2 Candidate Design

V13.4.3 creates an evidence-based V0.2 candidate matrix for AlphaPilot Volume
Rebound. It uses the V13.4.1 diagnosis and V13.4.2 signal audit reports.

This version does not modify V0.1 strategy logic, does not change backtest
config defaults, does not run Dry-run, and does not connect to live trading.

## Inputs

```text
reports/v13_4_1_diagnosis_report.json
reports/v13_4_2_signal_audit_report.json
```

Both reports are from the real V13.4 smoke backtest and are marked
`isMock=false`.

## Outputs

```text
reports/v13_4_3_v02_candidate_matrix.json
reports/v13_4_3_v02_candidate_summary.md
docs/volume-rebound-v02-candidate-plan.md
```

## Command

```powershell
python -m alphapilot.reports.generate_v02_candidate_matrix
```

what to test, and do-not-assume guardrails.

## Main Evidence

- SOL is the largest losing pair in V13.4.1 and also has the most final entries
  and actual trades in V13.4.2.
- Stop-loss exits are the largest losing exit bucket.
- MACD two-candle weakness exits lost heavily in the smoke sample.
- The 1-3h holding bucket is the weakest holding bucket.
- Weak 4h trend is the largest primary skip reason.
- The no-chase filter is the least primary-blocking filter.
- Fees are material, and slippage was not applied in the V13.4 command.

## Safety Boundary

V13.4.3 reads local report files only.

It does not:

- tune V0.1 parameters
- modify `AlphaPilotVolumeReboundV01.py`
- modify `config.backtest.json`
- run backtests
- run Dry-run
- use real API keys
- call Trade API
- call Withdraw API
- read real accounts
- read real positions
- create real orders
- auto trade
- modify the mobile app
