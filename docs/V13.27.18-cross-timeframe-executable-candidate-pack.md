# V13.27.18 Cross-Timeframe Executable Candidate Pack

V13.27.18 turns the five-per-timeframe research inventory into executable,
auditable workflow definitions for `5m`, `15m`, `1h`, `4h`, and `1d`.

## Candidate inventory

- Exactly five immutable research candidates are registered per timeframe.
- Candidate count is not a formal-pass count.
- Historical development evidence currently classifies 13 definitions as
  research-eligible and 12 as shadow-only.
- Shadow-only definitions remain visible for comparison but do not gain formal
  promotion evidence from registration.

## Less-rigid signal design

Long-horizon candidates use event windows and staged confirmation instead of
requiring every indicator to agree on one candle.

- `1h` keeps the prior sweep/reclaim evidence and uses optional confirmation
  scoring where supported.
- `4h` uses a recovery/reclaim event window with broad trend, RSI, volume, and
  volatility ranges. Five holding/ATR variants share one correlation group and
  are not treated as five independent risk sources.
- `1d` uses breakout/retest, squeeze-release, and oversold sweep/reclaim
  families. The two oversold variants remain shadow-only because their
  development sample is small.

This reduces accidental signal starvation without relaxing the formal
evaluation gates.

## Formal data plans

- `5m`: signal and execution data at `5m`.
- `15m`: signal at `15m`, execution at `5m`.
- `1h`: signal at `1h`, execution at `5m`, fallback at `15m`.
- `4h`: signal at `4h`, execution at `15m`, fallback at `1h`.
- `1d`: signal at `1d`, execution at `1h`, fallback at `4h`.

The `4h` override is explicitly allowlisted and fail-closed. Invalid or
mismatched overrides are rejected. Formal history is reused from
`D:\Codex-Workspace\回测数据\_alphapilot`; missing official partitions are
downloaded through the existing restart-safe collector.

Formal candidate discovery uses only public OKX data. It filters USDT swaps to
OKX `instCategory=1` crypto instruments, then ranks the live list by estimated
24-hour quote notional (`last * volCcy24h`). The ranking algorithm is versioned
inside the strategy data contract, so prior alphabetical-universe checkpoints
cannot silently contaminate the corrected run.

This Top50 is a snapshot at collection time. It is not a reconstructed
historical point-in-time membership series, so it still carries current-listing
and survivorship limitations. Formal results from this pack must retain that
limitation and require separate historical-universe robustness evidence before
any Live promotion decision.

## Evidence and promotion boundary

The candidate report binds every executable definition to its prior
development evidence. It does not use locked data for parameter selection and
does not claim formal promotion.

All definitions keep:

- `targetR >= 2R`;
- unchanged fee, slippage, and cost-stress checks;
- walk-forward and symbol-holdback requirements;
- immutable strategy versions and frozen formal snapshots;
- no Demo or Live release from research screening.

No API key, private account state, position state, order creation, Withdraw
API, Demo transition, or Live activation is introduced by this version.

## Commands

Generate the reproducible candidate report:

```powershell
.venv\Scripts\python.exe -m alphapilot.reports.generate_v13_27_18_cross_timeframe_candidate_pack
```

Register the 25 immutable research versions idempotently:

```powershell
.venv\Scripts\python.exe -m alphapilot.evolution.workflow.cli bootstrap-v13-27-18-cross-timeframe
```

Formal backtests should be run serially, starting with the strongest existing
evidence in each long-horizon timeframe. One data-prefetch worker may run in
parallel, but only one formal evaluator writes promotion evidence at a time.
