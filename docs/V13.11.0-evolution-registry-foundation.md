# AlphaPilot V13.11.0 Evolution Registry Foundation

V13.11.0 establishes an immutable research registry for the future Factor
Evolution Research Kernel. It indexes existing local research artifacts without
turning them into runnable strategies.

## Scope

- Versioned SQLite migrations for research metadata.
- Typed immutable repositories with content-hash conflict checks.
- SHA-256 data snapshot manifests and verification.
- Legacy JSON artifact classification and exact-rule deduplication.
- A reproducible registry foundation report.

This phase does not change strategy logic, run backtests, train models, create
Demo releases, create orders, or connect to private exchange endpoints.

## Registry Tables

The registry initializes these append-only or immutable metadata tables:

```text
DataSnapshots
FactorDefinitions
FactorRuns
Experiments
Models
StrategyFamilies
StrategyCandidates
PromotionDecisions
DemoReleases
LiveCandidatePackages
DriftEvents
AuditEvents
LegacyEvidence
```

`RegistryMigrations` records applied schema versions. Migrations run in a
transaction and fail closed. Existing project databases are not modified.

## Legacy Evidence Rules

Historical reports remain unchanged on disk. The importer records source path,
source SHA-256, canonical content hash, classification reasons, strategy-family
fingerprint, and rule fingerprint.

Classifications are:

- `factor_asset`
- `strategy_candidate_evidence`
- `duplicate_family_member`
- `report_summary`
- `incomplete_evidence`

Top-level array logs are retained as research evidence but can never become a
strategy candidate in Phase 1. JSON containing non-standard `NaN` values is
reported as invalid instead of silently replacing the missing value.

Even complete legacy rule evidence remains `legacy_evidence_only`. It still
requires a formal strategy contract, point-in-time validation, semantic and
correlation deduplication, purged walk-forward evaluation, cost stress, and
multiple-testing controls.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_evolution_registry_foundation.ps1
```

When system Python is unavailable, pass the verified runtime explicitly:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_evolution_registry_foundation.ps1 -PythonPath "C:\path\to\python.exe"
```

Outputs:

```text
data/evolution_registry.sqlite
reports/evolution_registry_foundation_report.json
reports/evolution_registry_foundation_summary.md
```

The SQLite file is local and ignored by Git. The generated JSON and Markdown
reports are committed as auditable build results.

## Safety Boundary

- Research-only local metadata.
- No API key use or storage.
- No Trade API or Withdraw API.
- No account, position, or balance reads.
- No StrategyCandidate auto-creation from legacy reports.
- No Demo or live release promotion.
- No order creation or automatic trading.

Phase 2 can now build the restricted Factor DSL and point-in-time evaluation
kernel on top of stable, content-addressed research records.
