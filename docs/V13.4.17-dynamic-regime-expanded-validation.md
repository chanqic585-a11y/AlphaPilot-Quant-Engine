# AlphaPilot V13.4.17 - Dynamic Regime Expanded Validation

V13.4.17 runs an expanded local Freqtrade validation for
`AlphaPilotDynamicRegimeV01`.

## Scope

```text
strategy: AlphaPilotDynamicRegimeV01
timeframe: 1h
timerange: 20260101-
universe: historical dynamic universe selectedPairs union
slippage stress: 0.05%, 0.10%, 0.20%, 0.30% one-way
```

The backtest pair list is the union of all selected pairs in the historical
dynamic universe snapshots. The strategy still filters each candle by the
snapshot date, so this does not turn the test back into a static Top 30 run.

## Commands

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_dynamic_regime_expanded_validation.ps1 -Timerange "20260101-" -Run
python -m alphapilot.reports.generate_dynamic_regime_expanded_report
```

## Outputs

```text
reports/v13_4_17_dynamic_regime_expanded_report.json
reports/v13_4_17_dynamic_regime_expanded_summary.md
```

The report contains:

## Quality Gate

V13.4.17 evaluates a research quality gate:

```text
slippage-adjusted return > 0
slippage-adjusted profit factor > 1.15
max drawdown acceptable
max consecutive losses acceptable
no pair/month dominates
trade count meaningful
```

This quality gate is for research review only. It never approves Dry-run.

## Safety Boundary

V13.4.17 uses local public historical data and local Freqtrade backtesting only.
It does not use real API keys, call Trade API or Withdraw API, read accounts,
read positions, create orders, enter Dry-run, or auto trade.
