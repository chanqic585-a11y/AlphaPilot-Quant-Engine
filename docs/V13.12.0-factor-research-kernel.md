# AlphaPilot V13.12.0 Factor Research Kernel

V13.12.0 adds the fail-closed research primitives required before automated
factor search can begin. It does not claim that an expression is profitable
merely because the DSL can represent it.

## Restricted Factor DSL

The parser is a custom data-only lexer and Pratt parser. It never calls Python
`eval`, `exec`, dynamic import, file APIs, process APIs, or network APIs.

Whitelisted canonical operators:

```text
lag, delta
rolling_mean, rolling_std, rolling_min, rolling_max, rolling_rank
zscore, correlation, decay_linear
cross_sectional_rank, group_neutralize
safe_add, safe_subtract, safe_multiply, safe_divide
safe_log, safe_sqrt, where
```

Legacy aliases such as `ts_mean`, `ts_std`, `ts_min`, `ts_max`, `rank`, and
`ts_return` are normalized to safe canonical operators. Attribute access,
strings, indexing, statements, arbitrary functions, and reserved Python names
are rejected by the lexer/parser.

The validator enforces field types, function arity, integer windows, a maximum
window, expression depth, node count, division/log/square-root domain metadata,
and non-negative lag/delta offsets.

## Point-In-Time Boundary

Every input field requires `availableAt` or an explicit bar delay. Forward
labels and future offsets are blocked. Data snapshot cutoffs and dynamic
universe snapshots must be at or before the evaluation cutoff. Missing
historical-universe evidence fails closed.

## Evaluation Controls

- Expanding and rolling purged walk-forward manifests.
- Label-window purge plus holding-period embargo.
- Benjamini-Hochberg FDR.
- Deflated Sharpe probability container.
- PBO-like partition selection diagnostic.
- Seeded block bootstrap confidence intervals.
- Parameter-neighborhood stability.
- Pair, month, exchange, and Regime stability.
- Baseline, 2x cost, 3x cost, one-bar latency, extreme-gap, and consecutive-loss metrics.

Missing latency returns remain explicitly `missing_delayed_returns`; they are
not synthesized.

## Existing 16-Factor Baseline

The adapter reads the existing V13.7.13 factor definition and evaluation
reports. It registers exact source formulas and hashes without loading,
recalculating, or modifying factor values.

```text
factorCount: 16
dslSupportedCount: 11
dslBlockedCount: 5
legacyCandidateFactorCount: 0
formalResearchReadyCount: 0
factorValuesLoaded: false
valueMutationPerformed: false
```

Blocked formulas:

- `distance_to_ema20`: `ts_ema` is not whitelisted.
- `distance_to_ema50`: `ts_ema` is not whitelisted.
- `trend_strength`: `ts_ema` is not whitelisted.
- `mean_reversion_distance`: `abs` is not whitelisted.
- `relative_strength_vs_btc`: formula requires `btcReturn_12`, but the legacy definition declares only `btcReturn`.

These blocks are intentional. The adapter does not silently rewrite EMA or
repair inconsistent field declarations. DSL-compatible factors also remain
blocked from formal promotion because the legacy report does not contain the
new point-in-time, purged walk-forward, FDR, Deflated Sharpe, PBO, bootstrap,
and cost-stress evidence contract.

## Run

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_factor_research_kernel_baseline.ps1
```

Outputs:

```text
reports/factor_research_kernel_baseline_report.json
reports/factor_research_kernel_baseline_summary.md
```

The detailed legacy evaluation remains in its original report. The new report
stores only key metrics plus source paths and SHA-256 hashes to avoid copying a
large report into another large report.

## Safety Boundary

- No strategy behavior changed.
- No FactorDataPanel values changed.
- No StrategyCandidate or DemoRelease created.
- No API key use or storage.
- No Trade API or Withdraw API.
- No account, balance, position, or order access.
- No automatic or live trading.

V13.13.0 may use this kernel to generate restricted research candidates, but
the Bandit may allocate research compute only and cannot influence orders.
