# V13.27.8 Shared Official Market Data

## Purpose

V13.27.8 prevents strategy contracts from repeatedly downloading an identical
OKX public OHLCV history. It changes data acquisition only. It does not change
strategy rules, backtest gates, local-forward rules, Demo releases, risk
profiles, credentials or order permissions.

## Two-layer backtest data flow

1. Run the existing local, non-official research smoke. This is diagnostic and
   does not count as formal promotion evidence.
2. Resolve an existing OKX canonical partition by instrument and timeframe.
3. Validate the manifest identity, source endpoint, canonical-root containment,
   file existence and SHA-256.
4. Request only confirmed candles newer than the verified partition end time.
5. Reuse the immutable file when no tail exists, or merge the tail and write a
   new content-addressed canonical snapshot.
6. Run the existing formal validation and backtest workflow.

Partial page checkpoints are progress telemetry only. They are never shared or
counted as a completed formal partition. A missing, malformed, path-escaping or
hash-mismatched manifest falls back to a fresh official collection.

## Timeframe behavior

The same resolver is used for every supported timeframe, including `5m`,
`15m`, `1h`, `4h` and `1d`. All strategies requiring the same OKX instrument
and timeframe share the verified warehouse base regardless of strategy family.

The Alpha191 observation strategy has a `4h` signal timeframe, but its formal
data contract also requires `5m` execution data and `15m` execution fallback
data. It therefore reuses all three shared stores: `5m`, `15m` and `4h`.

## Selected workflow order

The current durable queue keeps these workflows selected:

1. `5m 极端超卖收回 ATR1.2`
2. `15m EMA20 回收反弹 ATR1.4`
3. `Alpha191 加密因子观察策略`

They may all be visible as active or queued workflows, but only one physical
official-data worker should download at a time. Later workflows discover and
reuse completed canonical partitions from earlier workflows, then request only
missing tails.

## Deployment verification

The merged V13.27.8 worker was started from a clean process after the previous
long-running batch exited. The selected 15-minute workflow advanced from 14 to
44 completed partitions in seconds while checking short missing tails, and the
process audit showed one logical batch worker. The other two selected workflows
remained in the same durable serial queue.

## Safety boundary

- OKX public market data only.
- No raw API key storage.
- No private account or position reads.
- No Withdraw API.
- No live order creation.
- No change to target R or promotion evidence requirements.
