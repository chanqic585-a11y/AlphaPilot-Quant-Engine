# V13.5.4 Local Paper Monitoring and Fresh Evidence Refresh

V13.5.4 turns the V13.5.3 one-shot local paper sandbox ledger into a repeatable
monitoring step.

This version is local simulation monitoring only. It does not run exchange
Dry-run, use API keys, read accounts, read real positions, create orders, or
auto trade.

## Objective

V13.5.4 monitors whether the V13.5.2 approved candidate remains suitable for
continued local paper observation.

It adds:

- Optional public 1h data refresh through the existing Docker/Freqtrade public
  data downloader.
- V13.5.2 forward-confirmation signal-log refresh.
- V13.5.3 local paper ledger refresh.
- Rolling-window metrics for recent 5, 10, 20, 30, and 40 closed simulated
  fills.
- Freshness checks for latest approved signal and latest closed simulated fill.
- Skipped-signal breakdown.
- A monitoring decision with warning and fail reasons.

## Run Commands

Preview:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_v13_5_4_local_paper_monitoring.ps1 -RefreshPublicData
```

Execute with public data refresh:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_v13_5_4_local_paper_monitoring.ps1 -RefreshPublicData -Run
```

The data refresh is public market data only. It does not use credentials and
does not connect to any private exchange endpoint.

## Public Data Refresh Note

The V13.5.4 run refreshed public 1h OKX futures data for the monitored local
universe. A spot check confirmed BTC/ETH/SOL 1h futures files through
`2026-07-05 16:00 UTC`.

The first refresh attempt failed because Docker Desktop was not running. The
runner now relies on `download_data.ps1` propagating Docker failures correctly,
so a failed public data refresh cannot silently continue as a successful
pipeline run.
