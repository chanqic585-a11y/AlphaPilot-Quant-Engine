# Probability Gate Candidate Backtest Plan

This document records the V13.4.21 backtest plan generated by V13.4.20.

V13.4.20 does not run this plan. It only prepares research-only configs and a
structured comparison plan.

## Variants

V13.4.21 should compare four variants:

| Variant | Purpose |
| --- | --- |
| `baseline_dynamic_regime_current_gate` | Existing `AlphaPilotDynamicRegimeV01` current probability gate |
| `probability_gate_c1_trend_medium_safe` | Coarse C research candidate |
| `probability_gate_d1_trend_module_low_safe` | Coarse D research candidate |
| `probability_gate_cd_trend_research_combined` | Combined coarse C + D research candidate |

## Smoke Scope

```text
pairs: BTC/USDT:USDT, ETH/USDT:USDT, SOL/USDT:USDT
timeframe: 1h
timerange: 20260401-
```

The smoke scope should verify that each candidate can be wired into a local
research backtest path without changing live trading boundaries.

## Expanded Scope

```text
pairs: historical dynamic universe selectedPairs union
timeframe: 1h
timerange: 20260101-
```

The expanded scope should evaluate whether the candidate gates improve actual
trade count and research metrics beyond the current zero-trade baseline.

## Required Metrics

V13.4.21 should report at least:

- trade count
- total return
- max drawdown
- win rate
- profit factor
- expectancy
- final entry signals
- probability pass count
- slippage-stressed results
- liquidity gate summary
- pair breakdown
- regime and module breakdown

## Promotion Boundary

Passing a backtest is not enough to approve Dry-run or live trading.

Any future promotion would require a separate review that checks out-of-sample
behavior, liquidity, slippage, drawdown, execution reality, risk limits, and
safety gates.
