# V13.15.0 Live Candidate Boundary

V13.15.0 introduces an immutable review package between completed OKX Demo
validation and any future live release design. It does not add a live exchange
connector.

## Hard gates

- The source `DemoRelease` must be registered and have status
  `demo_validated` or `demo_completed`.
- At least 50 Demo trades must be closed across at least 30 calendar days.
- Net profit factor must be at least 1.15 and maximum drawdown below 5%.
- Critical drift must be resolved.
- Ledger, release checksum, symbol, regime, and time stability checks must pass.
- The Demo outcome manifest and code/data/model lineage checksums must exist.
- A reviewed rollback release and bounded risk budget are mandatory.

## Risk ceiling

- Capital limit: 1000 USDT.
- Risk per trade: 0.25%.
- Total open risk: 1%.
- Maximum order notional: 250 USDT.
- Maximum positions: 3.
- Maximum leverage: 2x.
- Daily loss stop: 2%.
- Drawdown stop: 5%.

These values are a proposal attached to the immutable package. They are not an
execution permission.

## Approval boundary

The exported package declares manual approval required, automatic approval
disabled, live execution adapter absent, live execution disabled, and Withdraw
disabled. Control Console approval must bind the exact package checksum and
risk budget. A checksum change invalidates prior approval.

The current registry contains no package that passes all gates, so the baseline
report is blocked with zero candidates. This is expected and must not be
overridden with synthetic evidence.
