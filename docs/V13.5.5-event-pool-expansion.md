# V13.5.5 Event Pool Expansion

V13.5.5 expands public historical data coverage and converts the local data into
candidate-event pool diagnostics. The goal is not to tune a strategy until it
looks good. The goal is to answer whether AlphaPilot has enough broad,
non-concentrated event samples to continue local paper monitoring responsibly.

## What This Version Does

- Optionally refreshes public OKX futures OHLCV data for a broader liquid
  universe.
- Builds derivative feature panels from local public data.
- Labels candidate events with the existing 2R triple-barrier simulator.
- Reports event counts, pair coverage, month coverage, holdout sample size, and
  concentration risk.
- Separates sample sufficiency from target metrics.
- Uses a lower win-rate observation gate while keeping the 2R reward/risk
  requirement unchanged.
- Uses `1h` and `4h` by default; `15m` can be supplied manually for extra
  inspection but is intentionally not the default because it is heavier and
  noisier.
- Keeps exchange Dry-run and live trading disabled.

## What This Version Does Not Do

- It does not use API keys.
- It does not call Trade API or Withdraw API.
- It does not read real accounts or real positions.
- It does not create orders.
- It does not auto trade.
- It does not approve exchange Dry-run.
- It does not promise a fixed win rate or profit.

## Run

Preview only:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_v13_5_5_event_pool_expansion.ps1
```

Refresh public data and generate the report:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_v13_5_5_event_pool_expansion.ps1 -RefreshPublicData -Prepend -Run
```

Generate the report from existing local data:

```powershell
python -m alphapilot.reports.generate_v13_5_5_event_pool_expansion_report
```

## Target Metric Policy

V13.5.5 does not require 55% win rate for the event-pool diagnostic layer.
Because the target reward/risk remains 2R, a lower win-rate threshold is more
appropriate for research screening:

- target win rate: at least 45%
- target reward/risk ratio: at least 2.0
- target profit factor: at least 1.35
- target max drawdown: no more than 25%
- target total return: positive after modeled costs

Passing these metrics still does not approve exchange Dry-run or live trading.
It only marks a pool for forward confirmation.

## Anti-Overfit Checks

Each event pool records:

- total event count
- unique pair count
- unique month count
- single pair concentration
- single month concentration
- recent holdout trade count
- early, middle, recent, and yearly metrics

The report can mark a pool as sample-sufficient, but that is not the same as
trading approval. Target metrics need forward confirmation before any new local
paper candidate is promoted.

## Safety Boundary

V13.5.5 is research-only and local-data-only. It may refresh public historical
market data through Freqtrade, but it does not connect to private exchange
permissions, does not store real credentials, and does not create orders.
