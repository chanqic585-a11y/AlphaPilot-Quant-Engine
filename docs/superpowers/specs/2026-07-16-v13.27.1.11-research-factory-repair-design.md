# V13.27.1.11 Research Factory Repair Design (Revised V2)

## Status

Approved for implementation on 2026-07-16. Revised V2 is the canonical execution contract and supersedes the earlier V13.27.1.11 prompt wherever they differ.

## Objective

Repair the research methodology before running one bounded campaign over three falsifiable market-hypothesis families. The run may validly produce zero formal passes. It must not manufacture a winner, restore an old candidate, or create any Demo or Live approval.

## Baseline

- Quant and Console Phase 3/4 work is merged to `main` and tagged `v13.27.1.10`.
- The previous campaign produced zero formal passes and zero strategy-validation releases.
- Existing user edits to `reports/archived_failed_strategy_failure_attribution_summary.md` remain out of scope and unmodified.
- Existing Phase 3 artifact names are mapped explicitly to the V13.27.1.11 contract; missing artifacts are never silently invented.

The closeout state is captured before any new research work in machine-readable and Markdown manifests. The manifest records local and remote heads, tags, acceptance commands, preserved pre-existing changes, and whether each repository was safely closed. A blocked or ambiguous baseline stops the campaign.

## Input Artifact Mapping

Every required Phase 3/4 logical role is resolved to one actual artifact before methodology work starts. Resolution priority is: explicit user path, artifact-manifest path, unique schema fingerprint, then exact filename candidate. Each mapping records path, existence, SHA-256, file type, schema fingerprint, selection reason, and ambiguous candidates. Missing or unresolved required roles fail closed with `input_mapping_blocked`; empty placeholders and guessed substitutes are forbidden.

## Safety Boundary

- Public historical data only.
- No API credential input or persistence.
- No private account, balance, position, or order access.
- No Trade API, Withdraw API, Demo order, Live order, Dry Run, or automatic trading.
- A formal pass produces `formal_pass_evidence` only. It never imports into Console.
- All missing evidence remains `null` or `unavailable`; absence never defaults to pass.

## Architecture

The implementation extends `alphapilot/research_screening/` with focused modules for gate evaluation, formal data provenance, temporal splits, execution parity, multiple-testing control, exit geometry, portfolio evaluation, uncertainty, and artifact reproducibility. Existing Phase 3 modules remain readable and backward compatible, while new reports use an explicit V13.27.1.11 schema.

Data preparation is resumable and separate from result generation. Collection may use the network; frozen-campaign execution must run with the network guard enabled and may read only a registered immutable snapshot.

## Methodology Contract

### Hierarchical hypotheses

The campaign contains two top-level families and three directions:

- `stress_reversal`
  - `idiosyncratic_selloff_exhaustion_long` (A)
  - `short_crowding_unwind_long` (B)
- `cross_sectional_momentum`
  - `pit_liquid_cross_sectional_momentum` (C)

Testing proceeds top-level family, subfamily, then variant. Reports preserve raw, family-adjusted, subfamily-adjusted, and global-FDR-adjusted p-values. A/B event overlap and return dependence are measured explicitly. If event Jaccard is at least 0.50 or absolute event-return correlation is at least 0.80, both remain counted as tests but share one risk cluster and at most one may produce formal evidence under the preregistered selector.

### Gate separation

Metrics are stored as three disjoint objects:

- `developmentMetrics`: mechanism and exit-model selection only.
- `walkForwardMetrics`: stability and basic-gate evaluation.
- `holdoutMetrics`: one-shot final adjudication only.

The implementation must not concatenate or average walk-forward and holdout metrics. The clean holdout access count is persisted and must be zero before adjudication and exactly one after the final read.

Event-family gates and portfolio-family gates are separate typed contracts. Event thresholds are never applied to cross-sectional portfolio returns, and portfolio thresholds are never used to rescue event strategies.

Public gate fields are explicit: `developmentPrefilterPassed`, `walkForwardNumericPassed`, `simpleBenchmarkPassed`, `uncertaintyPassed`, `capitalCompetitionPassed`, `implementationParityPassed`, `formalDataProvenancePassed`, `cleanHoldoutPassed`, `overallBasicPassed`, and `overallFormalPassed`. Execution facts are separately recorded as `eventReplayExecuted`, `freqtradeBacktestExecuted`, `portfolioBacktestExecuted`, and `translationParityPassed`.

For A/B, the formal gate requires walk-forward PF at least 1.15, average net R at least 0.05, positive total net R, at least four of five positive folds, drawdown no more than 20%, positive clean-holdout PF/average/total net R with the timeframe-specific minimum event count, positive 1.5x-cost results, positive 90% cluster-bootstrap lower bounds, simple-benchmark superiority, capital competition, formal provenance, and translation parity.

For C, formal adjudication uses portfolio returns, relative benchmark excess, positive rebalance periods, drawdown, 1.5x costs, bootstrap excess-return bounds, beta, turnover, capacity, symbol/month contribution limits, and PIT provenance. It never requires per-trade R or a fixed per-symbol profit target.

### Temporal causality

- Every feature, universe membership decision, direction choice, and exit choice uses only information available before the decision timestamp.
- Signals execute no earlier than the next tradable bar.
- Walk-forward folds use purge and embargo windows sized from maximum lookback and holding horizon.
- Direction and exit selection occur only in development data.
- A clean time and/or symbol holdout is locked before campaign execution.
- Every observation carries `eventTimestamp`, `observedAt`, `publishedAt`, `availableAt`, `sourceTimestamp`, `ageSeconds`, and `publicationLagSeconds`.
- Only rows with `availableAt <= signalDecisionTime` may influence a decision.
- Settled funding is usable only after settlement; predicted funding is usable only when contemporaneous public availability is proven.
- OI with unproven publication latency is delayed by at least one source period.
- Current incomplete-bar liquidity never enters PIT selection.
- Events whose holding interval crosses a development, fold, or holdout boundary are dropped rather than truncated.

### Execution parity

Event families A and B require a real Freqtrade-compatible trade ledger. Trade identity fields must match exactly: signal ID, symbol, direction, decision bar, entry bar, and exit reason class. Numeric values use preregistered tolerances. Formal parity requires 100% trade-identity agreement and no unexplained extra or missing trades.

Exact identity also includes exit timestamp. Numeric tolerance is restricted to entry/exit price and gross, fee, funding, slippage, and net R. At least 99% must fall inside frozen tolerances and every remaining difference must be classified and explained; an unexplained difference fails closed.

Portfolio family C uses a dedicated portfolio engine. It can only be release-compatible if the AlphaPilot execution layer can represent its rebalance, sizing, hedge, and cost contracts faithfully.

### Risk and exit geometry

- Initial stop is frozen before entry and never widened.
- A larger stop distance proportionally reduces position size.
- Event families may take a partial at 1R, but the remaining directional position starts with a target of at least 2R.
- Structural and time exits are allowed only when preregistered.
- Cross-sectional portfolios use rebalance, ranking, beta, liquidity, and portfolio-risk exits rather than per-position R targets.
- MFE, MAE, threshold-hit times, stop-first conflicts, and post-stop recovery are recorded for every event.

## Hypothesis Families

### Shared super-family control

Families A and B are both stress-reversal hypotheses. They remain separately testable mechanisms, but also share one `stress_reversal` super-family for overlap measurement, deduplication, and multiple-testing accounting. Highly overlapping event sets cannot count as independent discoveries.

### Family A: idiosyncratic selloff exhaustion long

- A1 uses same-exchange real liquidation evidence.
- A2 uses OI decline plus volume/wick proxy evidence.
- A2 is permanently marked `proxy_liquidation` and can obtain at most `provisional_research_pass`.

### Family B: short crowding unwind long

Requires same-exchange perpetual OHLCV, funding, OI, spot OHLCV, basis, PIT universe, and execution-cost evidence. Missing a core field blocks formal readiness.

### Family C: PIT liquid cross-sectional momentum

Uses a point-in-time high-liquidity universe, explicit capital competition, portfolio concurrency, turnover, funding, beta, concentration, and capacity constraints. Alpha088 is only a seed and must be re-evaluated on the new panel.

## Data Contract

The preferred source is OKX public market data. Each formal candidate uses one exchange for its core OHLCV, funding, OI, perpetual price, and trading-state data. Cross-exchange mixtures are rejected unless the cross-exchange relation itself was preregistered.

The data audit records availability, coverage, cadence, timestamp semantics, survivorship risk, delisting state, and provenance hashes for:

- perpetual and spot OHLCV;
- funding;
- open interest;
- basis;
- liquidation or explicit proxy;
- historical instrument state and PIT liquidity universe;
- spread, depth, slippage, and volume evidence.

If fewer than two families are formally data-ready, the campaign stops before preregistered evaluation and emits `data_not_ready` artifacts.

All data types declare `diagnostic_ready`, `provisional_ready`, `formal_ready`, or `unavailable`. A2 liquidation proxies can never exceed provisional status. B requires same-exchange funding, OI, perpetual price, spot price, and basis. C requires historical PIT tradability, liquidity, listing/delisting state, and the contemporaneous contract universe; a current-Top-N historical backfill is provisional only.

Before collection, an API capability audit records endpoint, history depth, pagination, rate limits, authentication needs, coverage, and limitations. Preparation scans existing data first, deduplicates on exchange/instrument/data-type/timestamp, enumerates gaps, and downloads only missing ranges. It is checkpointed, resumable, bounded by request/retry/disk budgets, and never deletes user data.

## Evaluation

- Three families, at most two variants per family.
- At most two exit models per family, selected deterministically on development data.
- At most 48 formal trials.
- No grid search, genetic search, post-holdout tuning, fourth family, or retrospective symbol removal.
- Base, 1.5x, and 2x cost scenarios are mandatory.
- Simple baselines include no-trade, directional exposure, and family-appropriate naive references.
- Uncertainty uses cluster/block bootstrap appropriate to event, symbol, month, or rebalance dependence.
- Portfolio metrics include capital competition, concurrent exposure, cross-strategy correlation, beta, turnover, and capacity.
- A/B simple baselines include unconditional rebound, BTC-beta/down-move matched, and residual mean reversion; B also reports funding-only reversal when available.
- C compares primarily with ordinary 20-day PIT cross-sectional momentum under the same universe, rebalance, exposure, beta, and cost assumptions. NoTrade, PIT equal-weight, BTC, and ETH are context baselines.
- Cluster bootstrap uses at least 5,000 preregistered draws and reports 80%, 90%, and 95% intervals using month, symbol/event cluster, or rebalance/correlation-cluster units as appropriate.
- Capital competition is deterministic and preregistered, including initial capital, risk per trade, concurrency, open/same-direction/correlation-cluster/symbol risk, beta, and liquidity capacity. Candidate ordering may use only contemporaneously available data.

## Artifact Contract

Every campaign writes JSON plus a readable Markdown summary. Tabular candidate results use Parquet only when the pinned `pyarrow` dependency is available; otherwise the run writes deterministic CSV and JSON sidecars and records Parquet as unavailable. An artifact manifest records SHA-256, schema version, generating command, Python/dependency versions, Git commit, snapshot hash, and preregistration hash.

The previous Phase 3 filenames are mapped explicitly:

- `data_source_audit.json` -> `data_audit.json`
- `dataset_catalog.json` -> `data_manifest.json`
- `phase3b_exit_gate.json` -> `family_eligibility.json`

Compatibility artifacts preserve the original source path and hash; they do not rewrite historical evidence.

## Campaign Closure

The clean holdout is opened once. After final adjudication the campaign is closed and immutable. A failed campaign may not add variants, change parameters, change exits, remove symbols, or rerun the holdout. Follow-up work requires a new campaign ID and new locked evidence.

The prior holdout is already observed, so this campaign uses a locked new-symbol holdout (recommended 70% research symbols and 30% symbol holdout), optionally followed by genuinely future data. Before unlock, Git, snapshot, preregistration, strategy, exit, benchmark, risk/capital, and environment hashes are frozen. The audit starts at access count zero and reaches exactly one. Only a byte-identical, pre-metric technical failure may be replayed, with an incident hash.

## Bounded Campaign Budget

- 2 top-level families, 3 directions, at most 2 variants per direction.
- At most 2 exit models per event direction, with one selected on development data before walk-forward.
- At most 20 complete event-strategy backtests and 12 portfolio backtests.
- At most 48 formal trials total.
- No fourth direction, symmetric-short copy, genetic search, broad grid search, retrospective symbol removal, or post-holdout tuning.

## Acceptance

- All methodology tests pass, including leakage, parity, provenance, multiple testing, exit geometry, budget, and zero-release paths.
- Data readiness is reported honestly for every required field.
- Campaign execution is offline and reproducible from frozen artifacts.
- Zero, provisional, research, and formal outcomes are distinct.
- No Demo or Live side effect exists.
- Full tests, compileall, config validation, safety scan, and `git diff --check` pass.
