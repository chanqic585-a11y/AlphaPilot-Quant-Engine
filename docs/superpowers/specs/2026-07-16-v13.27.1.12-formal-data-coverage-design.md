# V13.27.1.12 Formal Data Coverage Design

## Status

Approved by the user-provided canonical prompt:
`AlphaPilot_V13.27.1.12_Revised_Formal_Data_Coverage_PIT_Qlib_Readiness_Codex_Prompt_CN.md`.

## Goal

Turn the V13.27.1.11 fail-closed `data_not_ready` result into an auditable
answer about whether public historical data can make at least two top-level
research families formally ready. This version prepares data only. It does not
run strategy campaigns, unlock holdout data, create releases, arm Demo, or
create orders.

## Chosen Approach

Use a staged, same-exchange, evidence-first pipeline:

1. Map and hash every required V13.27.1.11 input.
2. Audit public API/archive capabilities separately from historical formal
   eligibility.
3. Select one exchange per formal core chain and reject cross-exchange splicing.
4. Reuse existing files, then collect only missing gaps under a frozen request,
   byte, disk, retry, and runtime budget.
5. Normalize causal availability clocks, build backward-only basis joins, and
   reconstruct PIT membership without today's TopN.
6. Apply source, instrument, family, and top-level readiness gates.
7. Freeze only audited inputs and emit a Qlib preflight decision without
   running a real Qlib campaign.

## Alternatives Rejected

- **Run Qlib immediately:** rejected because direction C lacks a formally
  verified historical PIT universe. A model run would be technically possible
  but scientifically invalid.
- **Fill gaps with proxies or mixed exchanges:** rejected because it would make
  the formal gate depend on non-comparable clocks and market microstructure.
- **Lower the 24-month and coverage gates:** rejected because the version is a
  data-readiness repair, not a threshold-optimization campaign.

## Components

- `input_artifact_mapping.py`: deterministic role-to-file selection, ambiguity
  detection, content hashes, and schema fingerprints.
- `source_capability_schema.py` and `source_selection_policy.py`: capability
  records and one-exchange formal-chain decisions.
- `checkpoint_store.py`, `resumable_collector.py`, `deduplication.py`, and
  `gap_repair.py`: non-destructive data acquisition primitives.
- `causal_availability.py` and `basis_builder.py`: strict availability clocks
  and backward as-of basis construction.
- `pit_universe.py`, `liquidation_evidence.py`, and `data_quality_gate.py`:
  historical membership, proxy separation, and formal quality evidence.
- `snapshot_freezer.py`: immutable, hash-addressed data-only snapshots.
- `qlib_adapter/preflight.py`: pinned Qlib metadata and launch gate only.
- `v13_27_1_12_reports.py`: canonical artifacts and final campaign decisions.

## Data Flow

Public source metadata and probes feed source selection. Existing files are
scanned before a collector requests any missing partition. Normalized records
carry `eventTimestamp`, `observedAt`, `publishedAt`, `availableAt`,
`sourceTimestamp`, and `publicationLagSeconds`. Quality and PIT audits feed
family readiness. Only after all audits finish can a data-only snapshot be
frozen and the Qlib launch gate evaluated.

## Failure Semantics

- Missing or ambiguous required input: `blocked_input_mapping`, stop.
- Budget, network, or rate-limit exhaustion: preserve checkpoint and report
  partial coverage.
- Missing historical PIT: C cannot be `formal_ready`.
- Missing same-exchange OI or basis: B cannot be `formal_ready`.
- Missing real liquidation: A1 cannot be `formal_ready`; A2 remains at most
  `provisional_ready`.
- Fewer than two formal top-level families: all formal campaigns remain closed.

## Verification

All production behavior is introduced test-first. Focused derivatives and
Qlib tests cover mapping, budgets, resume, deduplication, gap-only repair,
causal clocks, PIT anti-backfill, same-exchange selection, liquidation proxy
separation, readiness counting, LF output, stable hashes, Docker honesty,
holdout non-access, zero strategy trials, and zero orders. The full Python
suite, compileall, config validation, safety scan, and Git whitespace checks
must pass before tagging.
