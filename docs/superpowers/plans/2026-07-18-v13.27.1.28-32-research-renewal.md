# V13.27.1.28-32 Research Renewal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and run a bounded, auditable V28-V32 research-renewal program that either stops at exact Release-hash approval or closes with zero qualified candidates.

**Architecture:** Extend the existing candidate-neutral factory with versioned data, benchmark, candidate-type, OKX, and Release contracts. Keep orchestration separate from contract modules, preserve V27 evidence, and fail closed at every irreversible boundary.

**Tech Stack:** Python 3.12, dataclasses, pandas, existing AlphaPilot stable hashing and atomic JSON writers, pytest.

## Global Constraints

- Parent Program is `automatic_strategy_to_demo_v26_2aff44adf84d039c`; V27 is immutable and never rerun.
- Maximum 2 campaigns, 6 families/campaign, 2 variants/family, 12 initial candidates/campaign, 1 structural revision/family, 4 formal candidates/campaign, 48 full backtests/campaign, 96 additional full backtests, and 3 Demo releases/campaign.
- No gate lowering, result-driven symbol deletion, post-result candidate edits, forced winner, automatic approval, Demo ARM, Live, Withdraw, or real order.
- Formal Validation Core must not import S01-specific modules.
- New normal Git blobs must stay below 50 MiB.
