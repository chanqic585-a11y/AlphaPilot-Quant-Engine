# V13.27.1.34C Public Data Scheduler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an auditable, resumable public OKX data scheduler that collects only due incremental streams and emits immutable data-quality evidence without any research or trading side effect.

**Architecture:** A pure scheduling module decides due work from a versioned policy and atomic state. A focused incremental collector writes content-addressed public artifacts, while a separate quality monitor classifies freshness and integrity. A service orchestrator provides bounded one-cycle and explicit loop modes; it never installs an operating-system task automatically.

**Tech Stack:** Python 3.11, dataclasses, pathlib, atomic JSON checkpoints, pandas/pyarrow Parquet, existing `OkxPublicClient`, pytest.

## Global Constraints

- Public OKX `/api/v5/public/*` and `/api/v5/market/*` endpoints only.
- Preserve every V34A and V34B artifact byte-for-byte.
- PIT instrument history begins at observation time; never reconstruct unavailable prior state.
- Funding `realizedRate` becomes causally available no earlier than `fundingTime`.
- Candidate, Formal, result-read, Release, approval, Demo ARM, and order counts remain zero.
- Trade API, Withdraw API, API credentials, private account reads, and Locked OOS reads remain absent.
- Missing evidence stays missing or unavailable; the scheduler never fabricates a pass.

```python
@dataclass(frozen=True)
class TaskCadence:
    name: str
    interval_seconds: int
    retry_base_seconds: int
    max_consecutive_failures: int
    enabled: bool = True


@dataclass(frozen=True)
class OkxPublicCollectionPolicy:
    schema_version: str
    tasks: tuple[TaskCadence, ...]
    instruments: tuple[str, ...]

    @property
    def policy_hash(self) -> str:
        return stable_hash(asdict(self), prefix="v34c_collection_policy")
```

- [ ] **Step 4: Implement atomic state and exclusive lease**

`write_json_atomic`, and verifies the policy hash on load. `SchedulerLease`
uses `os.open(path, os.O_CREAT | os.O_EXCL | os.O_WRONLY)` and returns a bounded
owner audit when a lock already exists. It never silently steals a stale lock.

- [ ] **Step 3: Implement quality metrics and mechanical status rules**

`healthy` requires no overdue task, no active failure, and valid artifact
hashes. `warning` covers bounded lateness or one recoverable failure.
`degraded` covers lateness beyond four task intervals or repeated failures.
`blocked` covers artifact hash mismatch, invalid policy/state identity, or
causal/provenance schema failure.
