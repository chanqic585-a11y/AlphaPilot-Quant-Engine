# Candidate Evidence Closure Methodology

本流程用于复核已经归档、且历史失败主因被归类为风险模型问题的策略。它是研究审计，不是策略复活、参数搜索或执行批准。

## 固定流程

1. 从失败归因报告和演化注册表自动发现候选。
2. 按策略家族、父子链、信号定义和参数定义去重；自动优化子版本不重复计票。
3. 冻结候选身份、信号定义、数据快照、分割、成本模型、风险模型和通过门槛。
4. 在读取锁定结果前提交预注册文件和哈希。
5. 依次评估信号层、锁定样本层、成本压力层、Walk-forward 稳定性、主风险模型、Monte Carlo 和组合风险。
6. 使用固定状态机输出继续归档、局部优势但不稳定、信号通过但风险失败或证据闭环通过。

任何硬门槛失败都不能由另一个风险模型、删除亏损币、事后改阈值或历史高 PF 挽救。

## 可复现性

- 预注册哈希：`f869efb60ec4aedd20777b3dd3939b03aec10d8232c2220cf78a96d69c956f9b`
- Bootstrap：5,000 次，使用登记种子。
- Monte Carlo：每个候选/风险模型 5,000 次，使用登记种子。
- 执行过程支持哈希绑定的 checkpoint/resume。
- 数据、分割、成本和风险模型均保存哈希。
- `reports/generated/` 保存逐笔与抽样 JSONL；Git 只保存行数、SHA-256 和三条样本。

## 基线与缺失值

NoTrade 和简单方向持有基线用于比较，但不授予通过。无法从现有证据严谨计算的 DSR、PBO、BTC beta、资金费或 point-in-time 宇宙字段保持 `null` 并记录原因，禁止用零或乐观估计填充。

## 安全边界

流程不会恢复原归档策略，不创建可执行 StrategyVersion、Demo Release、Live Release 或订单，不接 Trade/Withdraw API，不读取账户或持仓，不保存 API Key。
