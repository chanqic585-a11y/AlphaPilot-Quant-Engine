# V13.5.6 High Reward Event Redesign

V13.5.6 keeps AlphaPilot on the research-only path and tests whether redesigned
event structures can support a fixed 2R target on broader public historical
data.

## Purpose

V13.5.5 showed that the previous event definitions had enough sample breadth,
but did not produce a 2R structure. V13.5.6 therefore adds event definitions
that are explicitly shaped around high reward/risk conditions:

- failed breakdown reclaim
- failed breakout rejection
- capitulation reversal
- blowoff reversal
- trend pullback acceleration

The target remains fixed at 2R. Win rate may be lower than earlier hard gates,
but the report does not lower the reward target to make results look better.

## What This Version Does

- Adds candle anatomy and prior-range features to the derivatives feature panel.
- Adds high-reward event setup definitions.
- Labels events with the existing triple-barrier simulator.
- Tests `1h` and `4h` public local data by default.
- Separates sample sufficiency from target-quality screening.
- Reports modeled-cost effects on the observed net reward/risk ceiling.
- May mark a fixed exploratory filter for local paper watch only.
- Keeps exchange Dry-run and live trading disabled.

## What This Version Does Not Do

- It does not use API keys.
- It does not call Trade API or Withdraw API.
- It does not read real accounts or real positions.
- It does not create orders.
- It does not auto trade.
- It does not approve exchange Dry-run.
- It does not promise a fixed win rate or profit.

## Target Policy

The gross target remains:

```text
targetRMultiple = 2.0
```

Because modeled roundtrip fee and slippage reduce average net winners and
increase average net losers, the report also records:

```text
costAdjustedTheoreticalRewardRiskRatio
observedToCostAdjusted2RCloseness
```

This is an accounting clarification, not a target relaxation.

The report may approve an exploratory local paper watch candidate when a fixed
filter has broad enough samples and acceptable recent behavior. That approval is
only for local simulated observation. It is not exchange Dry-run, live trading,
order creation, or automation.

## Safety Boundary

V13.5.6 is local-data research only. It uses public historical data already
stored under the Quant Engine workspace. It does not connect to private
exchange permissions, does not store credentials, and does not create orders.
